# 文字コード変換・確認ツール 要件

元の企画書：[requirements.md](requirements.md)。技術構成は [software-stack.md](software-stack.md) を参照。

## 目的
- ある文字の正体（文字コードの値や見た目）を確かめる。
- 文字と文字コードの値を、どちら向きにも変換して確かめる。

## 利用者
- 未確認（本人だけか、同僚にも配るか）。toolbox の一ツールとして zip に入れて配れる形で作る。

## 主要な利用の流れ
1. 文字欄に文字（1文字〜短い文章）を打つか貼り付ける → 各コード欄と「1文字ずつの一覧」が更新される。
2. どれかのコード欄（例：Shift_JIS 欄に `82 A0`）を書き換える → 文字欄とほかのコード欄が更新される。
3. 必要に応じてフォントを切り替え、大きく表示した形で見え方を確かめる。

## 扱う範囲 / 今は扱わないこと
扱う
- 文字 → コード、コード → 文字の両方向の変換（欄どうしが連動する一つの画面）
- Unicode の番号（U+XXXX）、UTF-8、UTF-16、Shift_JIS（Windows 版＝CP932）
- 表記の形、大きく表示した形、文字の素性、フォントの選択

今は扱わない
- ファイルを入れて読み直す・保存し直す
- EUC-JP、JIS（ISO-2022-JP）。必要になったら欄を足す
- 文字の名前（例：HIRAGANA LETTER A）。名前データの埋め込みで配布物が大きくなるため後回し
- 由来の分からない値を貼って、文字コードを推測する使い方（入力欄を一つにした自動判別はしない）

## 必要な機能と主要な振る舞い
- **連動する欄**：「文字」「U+番号」「UTF-8」「UTF-16」「Shift_JIS」の欄を並べる。どれか一つを書き換えると、残りの欄がすぐ更新される。欄ごとに文字コードが決まっており、入力の意味を推測しない。
- **1文字ずつの一覧**：文字欄の内容を1文字ずつに分け、文字・各コードの値・素性を並べる。
- **Shift_JIS**：Windows 版（CP932）として扱う。機種依存文字（①、㈱、Ⅰ、髙、﨑 など）もコードを出す。同じ文字に二つのコードがある場合、コード → 文字はどちらからも引け、文字 → コードは Windows と同じ代表を出す。
- **表せない・読めない入力**：Shift_JIS で表せない文字（例：𠮷、絵文字）は「表せない」と示す。読めないバイト列や形式の誤った値は、どこが読めないかを示し、推測で別の文字にしない。
- **表記の形**：`あ`（プログラム）、`%E3%81%82`（URL）、`&#12354;`（HTML）などを出す。
- **大きく表示した形**：文字を大きく表示する。
- **文字の素性**：全角か半角か、機種依存文字か、Shift_JIS で表せるか、文字の種類（ひらがな・漢字など）を出す。
- **フォントの選択**：PC に入っているフォントの一覧から選んで表示を切り替える。一覧が使えない環境では、フォント名を手で入力して切り替える。

## 完了条件
1. 文字欄に文字や文章を入れると、U+番号・UTF-8・UTF-16・Shift_JIS の欄と1文字ずつの一覧が更新される。どれかのコード欄を書き換えると、文字欄とほかの欄が更新される。
2. Shift_JIS で表せない文字は「表せない」と示し、読めないバイト列はどこが読めないかを示す。
3. 代表的な文字（あ・ｱ・①・髙・𠮷 など）が既知の値と一致することを自動テストで確かめる。Shift_JIS は Microsoft が公開している CP932 の対応表と全文字を突き合わせ、代表の選び方も含めて一致を確かめる（表はテスト用で、配布物に入れない）。
4. 表記の形、大きく表示した形、素性、フォントの選択が表示される。フォント一覧が使えない環境では、フォント名の手入力で切り替えられる。
5. `node scripts/toolbox.mjs check mojicode-converter` が通り、`tools.json` に登録されている。ネットにつながない状態で、`file://` から Windows の Edge と Mac の Chrome で動く。

## 制約
- 迷ったときの軸：出てくる値が正しいこと（Windows で確かめた値と同じになること）。
- toolbox 共通の約束：インストール不要、オフライン・`file://` で動く、Windows と Mac の Chrome・Edge で動く、CDN・外部サイトを読み込まない、入力した文字を外部へ送らない。
- toolbox の[ツール追加の手順](../../../docs/development.md#ツールを追加する)と共通 UI（`ui/`）に従う。

## 実装時に委ねること
- 画面の細かな配置、欄の並び順、1文字ずつの一覧の列構成。
- 各コード欄で受け付ける書き方の幅（区切りの空白・`0x` の有無・大文字小文字など）。意味があいまいにならない範囲で決める。
- 「文字の種類」の分け方の細かさ、代表的な文字のテスト例の追加。
- 表記の形として出す種類の細部（上の3種を最低限とする）。
