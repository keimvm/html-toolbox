# 文字コード変換・確認ツール 技術構成

元の企画書：[requirements.md](requirements.md)。満たす要件は [software-requirements.md](software-requirements.md) を参照。

## 選定に関わる制約

- 単一 HTML で配り、オフライン・`file://`・Windows/Mac の Chrome・Edge で動かす。外部を読み込まない。
- 依存関係は `tools/mojicode-converter/` の中で閉じる。共通の見た目・ヘッダー・ダークモードは `ui/` を取り込む（[開発・リリース手順](../../../docs/development.md)）。
- 値の正しさ（Windows と同じ値）を最優先する。

## 採用する技術

| 担当       | 技術                                                                    | 役割・採用理由                                                                   |
| ---------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 画面・処理 | TypeScript ＋ HTML ＋ CSS                                               | バイト列・数値の変換が中心のため、型の検査で取り違えを防ぐ                       |
| ビルド     | Vite ＋ vite-plugin-singlefile                                          | 単一 HTML にまとめる。PDF編集と同じ構成で、設定と `ui/` の取り込み方を流用できる |
| 自動テスト | Vitest                                                                  | 既知の値・CP932 対応表との突き合わせ                                             |
| 依存管理   | pnpm（版は `packageManager` で固定）、Node.js（`.node-version` で固定） | toolbox のツール追加の手順に従う                                                 |

実行時のライブラリは追加しない。以下はブラウザーの標準機能でまかなう。

| 役割                    | 標準機能                                                                                  | 補足                                                                                                                                              |
| ----------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| UTF-8 / UTF-16 / U+番号 | `TextEncoder`・`TextDecoder`・文字列のコードポイント操作                                  |                                                                                                                                                   |
| Shift_JIS（CP932）      | `TextDecoder('shift_jis')`                                                                | 全コードを一度読み、逆引きの表を実行時に作る。両方向が同じ表に基づくので食い違わない。同じ文字に二つのコードがある場合の代表は Windows に合わせる |
| 文字の種類・全角半角    | 正規表現の Unicode プロパティ（`\p{Script=...}` など）、`String.prototype.normalize` など | 機種依存文字かどうかは Shift_JIS の表（NEC・IBM 拡張の範囲）から判定する                                                                          |
| 表記の形                | 文字列処理、`encodeURIComponent` など                                                     |                                                                                                                                                   |
| フォントの一覧          | Local Font Access API（`window.queryLocalFonts()`）                                       | 初回に利用者の許可が要る。使えない・拒否されたときはフォント名の手入力に切り替え、CSS の `font-family` で表示する                                 |

## フォント一覧の権限・対応環境

- `queryLocalFonts()` は一覧ボタンを押したときだけ呼ぶ。返されたメタデータのうち `family` だけを候補にし、`FontData.blob()` によるフォントの実データの取得はしない。候補は画面を閉じるまでのメモリー上にだけ保持し、保存・外部送信しない。
- 配布 HTML の CSP は `connect-src 'none'` で通信を制限し、外部スクリプトも読み込まない。フォントの表示は既存の CSS `font-family` に任せる。
- API の許可範囲には一覧とフォントの実データへのアクセスが含まれ、名前だけに限定した権限ではない。一般のサイトでは一覧が端末の識別や所属組織の推測に利用されるリスクがある。通常は初回にブラウザーが許可を求め、許可が保持される場合はブラウザーの権限設定から取り消せる（[Chrome の公式説明](https://developer.chrome.com/docs/capabilities/web-apis/local-fonts)）。
- Windows・macOS のデスクトップ版 Chrome・Edge が対応する。API の対応と、このツールの `file://`・会社 PC での実機確認は分けて扱う。Edge は管理ポリシーでも一覧取得を禁止できる（[DefaultLocalFontsSetting](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/DefaultLocalFontsSetting)）。
- API が存在しない場合は一覧ボタンを隠す。拒否・制限・取得失敗の場合はメッセージを出し、フォント名の手入力と文字コード変換はそのまま利用できる。

## Shift_JIS の表の作り方

- 2バイトの全ての並び（リードバイト 81〜9F・E0〜FC × トレイルバイト 40〜7E・80〜FC）を改行で区切って `TextDecoder('shift_jis')` で一度に読み、1文字になったものを表に入れる。起動時に作り、両方向とも同じ表を引く（`src/sjis.ts`）。
- 1バイトの文字は WHATWG の定義どおり、00〜80 をそのまま、A1〜DF を半角カタカナ（U+FF61〜）として計算で求める。Node.js の `TextDecoder`（ICU）は `1A`・`1C`・`7F` を入れ替え、`80` を読まないため、自動テストの結果がブラウザーと食い違わないようにする。
- 文字 → コードは、その文字を表すコードのうち、NEC選定IBM拡張文字（ED40〜EEFC）を除いた最も小さいコードを代表にする（WHATWG の Shift_JIS の符号化と同じ）。JIS X 0208 → NEC特殊文字 → IBM拡張文字の順になる。

## テスト用の外部データ

- Microsoft の CP932 対応表 `CP932.TXT` と、Windows の変換表 `bestfit932.txt` を `tests/fixtures/` に置き、テストの正解として使う。配布物には入れない。入手元・取得日・SHA-256・利用条件は [tests/fixtures/README.md](../tests/fixtures/README.md) に記録した。
- `tests/sjis.test.ts` で、コード → 文字は `CP932.TXT` の全7,915コード、文字 → コードは `bestfit932.txt` の WCTABLE のうち往復できる全対応（代表の選び方を含む）と一致することを確かめる。

## 対応表との差（2026年9月26日に確認）

| コード                                                   | `CP932.TXT` | Windows（`bestfit932.txt`） | ブラウザー標準（WHATWG） | このツール                               |
| -------------------------------------------------------- | ----------- | --------------------------- | ------------------------ | ---------------------------------------- |
| `80`                                                     | 未定義      | U+0080                      | U+0080                   | U+0080（制御文字）として読む             |
| `F040`〜`F9FC`（外字）                                   | 未定義      | U+E000〜U+E757              | U+E000〜U+E757           | 私用領域として読み、素性に「外字」と示す |
| `A0`・`FD`〜`FF`                                         | 未定義      | U+F8F0〜U+F8F3（代替）      | 読めない                 | 読めない                                 |
| 未定義のリードバイト（`85`・`86`・`EB`・`EC`・`EF`）など | 未定義      | U+30FB（既定の代替文字）    | 読めない                 | 読めない                                 |

- 3者で定義のあるコードに食い違いはない。このツールで読めるのは `CP932.TXT` の全コードと `80`・外字の計9,796コードで、Windows の MBTABLE から代替の文字だけを除いたものと一致する。
- 文字 → コードの代表は、Windows の WCTABLE の往復できる対応と全て一致した。WCTABLE の best fit（例：`¥` U+00A5 → `5C`、`〜` U+301C → 近い文字）は往復しないため採用せず、「表せない」とする。
- 自動テストは Node.js の `TextDecoder` で表を作る。Chrome（Chromium）の `TextDecoder` で作った表も同じであることは、[検証記録](verification.md) の手順で確かめた。

## 未検証事項

- `file://` で開いたページで Local Font Access API が使えるか（安全な文脈として扱われるか）。会社の PC のブラウザー設定（管理ポリシー）で止められていないか。
- Windows の Edge、Mac の Chrome の各版の `TextDecoder` で表が一致すること（確認済みは下記の Chromium のみ）。

## 実装時に委ねること

- ファイル構成、関数・型の分け方、TypeScript・ESLint・Prettier などの細かな設定（PDF編集の設定を参考にする）。
- 逆引き表を作る時機（起動時か初回使用時か）と保持のしかた。
- 採用する pnpm・Node.js・各開発用パッケージの版。
