# プロンプト集の作業ガイド

最初に [README](README.md)、[要件](docs/software-requirements.md)、[技術構成](docs/software-stack.md)、[検証記録](docs/verification.md)、リポジトリ共通の [開発・リリース手順](../../docs/development.md) を読む。

- プロンプトの正本は、利用者が選んだフォルダの `prompt-library.json`。ブラウザー内（IndexedDB・localStorage）にはフォルダの記録だけを置き、プロンプトの本文を入れない。
- 追加・編集・削除は確定した時点で書き込む。画面全体の保存ボタンや下書きの保持を追加しない。書き込みは `changeLibrary()` で直前に読み直した内容に当て、ほかのタブの変更を消さない。
- 読めない保存ファイルは推測で直したり上書きしたりしない。保存ファイルの形を変えるときは `LIBRARY_VERSION` を上げ、古い形の読み込みと新しい版の拒否をテストで確かめる。
- フォルダの記録は、版（解凍先のフォルダ）をまたいで読めるよう固定のキーで持つ。`ui/session-key.js` の配置 URL を使わない。IndexedDB の読み書きは `ui/idb-record.js` を使う。
- 配色・ヘッダー左上の共通部品・ボタン・入力欄・ダイアログ・ポップオーバーは直下の `ui/` を使い、複製しない。
- 配布物は `dist/プロンプト集.html` の1ファイル。外部を読み込まず、プロンプトを外部へ送信しない。
- 要件の「今は扱わない」（毎回変わる部分をツール上で埋めてからコピーする機能、共有、保存ファイルを直接直す使い方）を実装しない。
- 通常は実装・必要なテスト作成・文書更新・差分の読み直し・コミットまでとし、テスト・lint・型チェック・ビルドは指示時のみ実行する。実行方法は共通の [開発・リリース手順](../../docs/development.md) に従い、未実行の確認は最終報告に明記する。自動テストはファイル API を模擬しているため、実フォルダ・`file://`・許可・コピーの確認は [検証記録](docs/verification.md) に分けて記録する。
- Playwright スキル・CLI はユーザーが明示的に使用を指示した場合だけ使う。
