# 画像変換ツール 要件

元の企画書：[requirements.md](requirements.md)。技術構成は [software-stack.md](software-stack.md) を参照。

## 目的

- 容量が大きくてメールや社内システムに添付できない画像・PDF を、容量と見た目をその場で確かめながら、添付できるファイルにする。

## 利用者

- 未確認（本人だけか、同僚にも配るか）。toolbox の一ツールとして zip に入れて配れる形で作る。

## 主要な利用の流れ

1. 写真・スクリーンショットを数枚から十数枚まとめて選ぶか、ドロップする → 一覧に並ぶ。
2. 全体の設定（出力形式、1枚あたりの容量の上限、長い辺の px）を一度指定する → 全画像に当たり、一覧に各画像の変換後の容量と見本が出る。上限に収まらない画像には印が付く。
3. 気になる画像だけを開き、拡大して元と見比べる。その画像だけ画質・大きさ・形式を変えたり、切り抜き・回転・塗りつぶしをしたりする。
4. 各画像の「保存」か、一覧の「すべて保存」でダウンロードする。

PDF は次の三つの使い方をする。

- 一覧の画像をまとめて1つの PDF にする。
- PDF のページを画像（JPEG・PNG）にする。
- 重い PDF を、PDF のまま小さくする。

## 扱う範囲 / 今は扱わないこと

扱う

- 画像のリサイズ・圧縮・形式変換。読み込みはブラウザーが開ける形式（JPEG・PNG・WebP・GIF・BMP など）、出力は JPEG・PNG
- 付加情報（Exif。位置情報・撮影日時・カメラ情報など）の削除
- 切り抜き・回転、画面の一部の塗りつぶし
- 画像 → PDF、PDF → 画像、重い PDF を小さくする

今は扱わない

- ファイル名の付け直し
- PDF の編集（ページの削除・並べ替えなど）。PDF編集ツールで行う
- WebP・AVIF の出力。添付先で開けない場合があるため
- HEIC（iPhone の写真）の読み込み。専用ライブラリの大きさとライセンスの負担が重いため
- 付加情報の一部（撮影日時など）だけを残すこと
- 作業状態の保存・再読み込み後の復元
- zip にまとめての保存

## 必要な機能と主要な振る舞い

- **まとめて設定、個別に直す**：全体の設定を全画像に当てる。個別に開いた画像で変えた設定は、その画像だけに効く。
- **容量の上限に合わせる**：JPEG は、上限以下に収まる最も高い画質を自動で選ぶ。長い辺の px を縮めても収まらない場合は、一覧で印を付ける。PNG は画質の段階がないため自動合わせの対象外とし、上限を超えたら印を付ける。
- **その場で確かめる**：一覧に変換後の容量と見本を出す。個別の画面で、元の画像と変換後の画像を拡大して見比べ、画質を手で動かせる。容量は設定を変えるたびに更新する。
- **元を壊さない**：元のファイルは読むだけで、書き換えない。保存はすべてダウンロード（`ui/download.js`）で、別のファイルとして作る。
- **付加情報**：書き出す画像には付加情報を一切残さない。写真の向き（Exif の回転指定）は、読み込み時に見た目どおりに直してから書き出す。
- **切り抜き・回転・塗りつぶし**：個別の画面で行う。塗りつぶした部分の元の画素は、書き出した画像に残さない。
- **画像 → PDF**：一覧の画像を、全体・個別の設定で縮めたもので、1枚1ページの PDF にする。ページの大きさは画像ごとにそのまま（余白なし）。PDF 全体の容量を表示する。
- **PDF → 画像**：PDF の各ページを JPEG・PNG にする。フォントを含まない PDF でも、日本語の文字が欠けないようにする。
- **重い PDF を小さくする**：PDF の中の写真・スキャン画像だけを縮め、JPEG にし直す。文字・図形はそのまま残し、選択・検索できる状態を保つ。縮められない画像（透過付きなど）は元のまま残す。変換前後の容量を表示する。
- **開けない形式**：HEIC など、ブラウザーが開けないファイルは「この形式は開けません」と案内し、ほかのファイルの作業は続けられる。
- **画面を離れるとき**：未保存の作業があるうちに画面を離れようとしたら、確認を出す。作業内容はブラウザー内に残さない。

## 完了条件

1. 写真とスクリーンショットを十数枚まとめて読み込み、全体の設定を一度指定すると、一覧に各画像の変換後の容量と見本が出る。JPEG は上限以下で最も高い画質になり、収まらない画像には印が付く。
2. 個別の画面で元と拡大して見比べ、画質を手で変えられる。切り抜き・回転・塗りつぶしができ、塗りつぶした部分の元の画素は書き出した画像に残らない。
3. 「すべて保存」で各画像が別々にダウンロードされ、元のファイルは変わらない。位置情報を含む Exif 付きの写真から書き出した画像に、Exif が残らず、向きが正しい。
4. 画像をまとめた PDF、PDF のページの画像が作れる。フォントを含まない日本語の PDF でも、文字が欠けずに画像になる。
5. 写真やスキャンの多い PDF を小さくすると容量が減り、文字は選択・検索できるまま残る。
6. `node scripts/toolbox.mjs check image-converter` が通り、`tools.json` と直下の README に登録されている。ネットにつながない状態で、`file://` から Windows の Edge と Mac の Chrome で動く。

## 制約

- 迷ったときの軸：手軽さ、仕上がりをその場で確かめられること、元の画像を壊さないこと。三つの優先順位は未確認。
- toolbox 共通の約束：インストール不要、オフライン・`file://` で動く、Windows と Mac の Chrome・Edge で動く、CDN・外部サイトを読み込まない、画像・PDF を外部へ送らない。
- toolbox の[ツール追加の手順](../../../docs/development.md#ツールを追加する)、[実装方針](../../../docs/development.md#実装方針)、共通 UI（`ui/`）に従う。

## 実装時に委ねること

- 画面の配置、一覧と個別の画面の切り替え方、見比べの表示のしかた（並べる・切り替えるなど）。
- 全体の設定の既定値（出力形式・容量の上限・長い辺）。
- 回転の単位、塗りつぶしの形と色、切り抜きの操作のしかた。
- 透過のある画像を JPEG にするときの背景色。
- 書き出すファイルの名前の付け方。
