# PDF編集の作業ガイド

直下の [AGENTS.md](../../AGENTS.md) に加える、このツール固有の約束です。

## 最初に読むもの

1. [README.md](README.md)：セットアップ、コマンド、ファイル配置。
2. [docs/software-stack.md](docs/software-stack.md)：現在合意している範囲と未決事項。
3. [docs/RFP.md](docs/RFP.md)：目的・背景。当初の要望を残した文書であり、初版の範囲はsoftware-stack.mdの具体化を参照する。
4. [docs/verification.md](docs/verification.md)：確認済みの範囲と検証手順。

作業前に`git status --short --branch`で既存の変更を確認する。ユーザーの変更を上書きしない。

## 環境

- 開発はmacOSを基本とし、Homebrewとpnpmを使う。
- 依存を変更するときは明示したバージョンを追加し、pnpm-lock.yamlも更新する。
- 初回の依存取得を除き、ビルドやテストで外部サービス・認証情報を必要とする構成にしない。

## 実装の原則

- 現在の要件を満たす最も単純な実装を選ぶ。仮の将来要件のための抽象化、互換層、フォールバックを作らない。
- 新しい依存や大きな仕組みを導入するときは、既存の構成では足りない理由を説明する。
- 復元用の配置URLは`ui/session-key.js`、ダイアログの操作欄は`ui/theme.css`を使う。PDF編集固有の操作はヘッダーの右側に置く。
- PDFエンジンは検証候補の段階。APIの存在だけで採用済み・動作確認済みと扱わない。
- 要素の個別削除、Markdown変換、OCRは初版では保留。依頼の範囲を越えて実装しない。

## 配布物の制約

- 成果物は`dist/PDF編集.html`の1ファイル。PDF、抽出内容、ファイル名を外部送信しない。アクセス解析や外部フォントも導入しない。
- `src/`等を変更し、`dist/`を直接編集しない。
- `public/`は使わない。Viteの通常のpublic資産は単一HTMLに埋め込まれないため、設定で無効にしている。
- Worker、WebAssembly、フォント等を追加したら、それぞれの埋め込みと`file://`での動作を次に検証を指示されたときの確認項目に含める。実行までは未確認とする。singlefileプラグインだけで全資産が埋め込まれると考えない。
- 業務データや個人情報のあるPDFをコミットしない。共有テストは合成PDFを使い、生成方法と期待結果を残す。

## 変更後の確認

- UI・PDFエンジン・配布方式を変えた場合は、ブラウザー操作、コンソールエラー、通信、配布HTMLの`file://`起動について必要な確認事項を整理し、検証結果を[docs/verification.md](docs/verification.md)に記録する。
- `pnpm check`にはブラウザー実行は含まれない。現在のビルドテストはファイル構成とscript/style参照の静的検査であり、実行時通信やPDF機能の検証とは別。

## ブラウザー作業

- Playwrightの使用を指示された場合はREADMEのPlaywright CLIの手順を参照する。セッション名を付け、作業後は自分のセッションだけを閉じる。
- スクリーンショット等の作業記録はGit管理対象外の`output/playwright/`へ保存する。
