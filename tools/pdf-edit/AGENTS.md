# エージェント向け作業ガイド

## 最初に読むもの

1. [README.md](README.md)：セットアップ、コマンド、ファイル配置。
2. [docs/software-stack.md](docs/software-stack.md)：現在合意している範囲と未決事項。
3. [docs/RFP.md](docs/RFP.md)：目的・背景。当初の要望を残した文書であり、初版の範囲はsoftware-stack.mdの具体化を参照する。
4. [docs/verification.md](docs/verification.md)：確認済みの範囲と検証手順。

作業前に`git status --short --branch`で既存の変更を確認する。ユーザーの変更を上書きしない。

## 言語と環境

- 応答・説明・画面文言は日本語を基本にする。コミットメッセージとPRも日本語で書く。
- 開発はmacOSを基本とし、Homebrewとpnpmを使う。配布物の対象はMac・WindowsのChrome・Edge。
- Node.jsとpnpmの条件はpackage.json、CIのNode.js版は.node-versionが正。
- 依存関係の復元は`pnpm install --frozen-lockfile`。依存を変更するときは明示したバージョンを追加し、pnpm-lock.yamlも更新する。
- 初回の依存取得を除き、ビルドやテストで外部サービス・認証情報を必要とする構成にしない。

## 実装の原則

- 現在の要件を満たす最も単純な実装を選ぶ。
- 関連コードと利用中の依存の標準APIを確認し、独自実装より既存の公開APIを優先する。
- OS・ブラウザー標準機能、ライブラリ、共通部品を優先する[共通の実装方針](../../docs/development.md#実装方針)に従う。標準・既存依存で足りなければ適切なライブラリを検討する。配色・ヘッダー左上の共通部品と表示の切り替え・ダイアログの操作欄・D&D・ダウンロード・配置URLの保存キーは直下の`ui/`を取り込み、複製しない。PDF編集固有の操作はヘッダーの右側に置く。
- 仮の将来要件のための抽象化、互換層、フォールバックを作らない。
- 新しい依存や大きな仕組みを導入するときは、既存の構成では足りない理由を説明する。
- PDFエンジンは検証候補の段階。APIの存在だけで採用済み・動作確認済みと扱わない。
- 要素の個別削除、Markdown変換、OCRは初版では保留。依頼の範囲を越えて実装しない。

## 配布物の制約

- 成果物は`dist/PDF編集.html`の1ファイル。利用時に外部サイト、CDN、サーバーを必要としない。
- PDF、抽出内容、ファイル名を外部送信しない。アクセス解析や外部フォントも導入しない。
- `public/`は使わない。Viteの通常のpublic資産は単一HTMLに埋め込まれないため、設定で無効にしている。
- Worker、WebAssembly、フォント等を追加したら、それぞれの埋め込みと`file://`での動作を確認する。singlefileプラグインだけで全資産が埋め込まれると考えない。
- `src/`等を変更し、`dist/`を直接編集しない。配布時は最新ソースからビルドする。
- 業務データや個人情報のあるPDFをコミットしない。共有テストは合成PDFを使い、生成方法と期待結果を残す。

## 変更後の確認

1. 必要な変更に応じたテストを`tests/`へ追加・更新する。単純な表示文言や整形だけの変更に形式的なテストを追加しない。
2. `pnpm check`を実行する。整形が必要なら`pnpm format`を実行し、差分を確認する。
3. UI・PDFエンジン・配布方式を変えた場合は、ブラウザー操作、コンソールエラー、通信、配布HTMLの`file://`起動について必要な確認事項を整理する。Playwrightによる確認は、ユーザーから明示的な使用指示を受けた場合に実行し、未実施の確認は未確認として記録する。
4. 仕様・手順・制約が変わった場合は該当文書を更新する。検証結果はdocs/verification.mdに記録する。
5. 最終報告に変更内容、検証結果、未確認事項を簡潔に書く。未実行のCIや対象OSでの確認を成功扱いしない。

`pnpm check`にはブラウザー実行は含まれない。現在のビルドテストはファイル構成とscript/style参照の静的検査であり、実行時通信やPDF機能の検証とは別。

## ブラウザー作業

- PlaywrightスキルとPlaywright CLIは、ユーザーが使用を明示的に指示した場合に限って使う。通常の開発・環境構築・検証では使用せず、エージェントが必要と判断しただけでは呼び出さない。
- 使用を指示された場合はREADMEのPlaywright CLIの手順を参照する。セッション名を付け、作業後は自分のセッションだけを閉じる。
- スクリーンショット等の作業記録はGit管理対象外の`output/playwright/`へ保存する。
- localhostでの動作、配布HTMLの直接起動、オフライン動作、対象OS・ブラウザーでの受入を区別して記録する。
