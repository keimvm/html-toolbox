# タイピングゲーム 技術構成

元の企画書：[requirements.md](requirements.md)。満たす要件は [software-requirements.md](software-requirements.md) を参照。

## 選定に関わる制約

- 単一 HTML で配り、オフライン・`file://`・Windows/Mac の Chrome・Edge 129 以降で動かす。外部を読み込まない。
- 依存関係は `tools/typing-game/` の中で閉じる。共通の見た目・ヘッダー・ダークモードは `ui/` を取り込む（[開発・リリース手順](../../../docs/development.md)）。
- 貼った文章と結果は保存しない。外部へも送らない。

## 採用する技術

| 担当       | 技術                                                                    | 役割・採用理由                                                                                                 |
| ---------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 画面・処理 | TypeScript ＋ HTML ＋ CSS                                               | プロンプト集・文字コード変換と同じ書き方にそろえる                                                             |
| ビルド     | Vite ＋ vite-plugin-singlefile                                          | 単一 HTML にまとめる。プロンプト集の `vite.config.ts`（CSP・配布ファイル名・`ui/` の取り込み）を流用できる     |
| 差分       | jsdiff（npm の `diff` 9.0.0）の `diffChars`                              | 文字単位の差分で、抜け・余分・打ち間違いを取り出す。理由は下記                                                 |
| 自動テスト | Vitest                                                                  | 判定（改行・空白の除去、正規化、差分）と進み具合の数え方                                                       |
| 依存管理   | pnpm（版は `packageManager` で固定）、Node.js（`.node-version` で固定） | toolbox のツール追加の手順に従う                                                                               |

### jsdiff を採用する理由

- 要件の「ずれを吸収して違う箇所だけを示す」には差分の計算が要り、ブラウザーの標準機能にはない。同じ役割を自前で実装しない。
- BSD-3-Clause、実行時の依存なし、型定義つき。2026年4月にも更新されている。
- `diff@9.0.0` で試した結果：「今日はいい天気」と「今日いい転気」から、「は」の削除、「天」の削除と「転」の追加を取り出せた。「𠮷」のような補助面の文字も1文字として扱う。
- 比べた候補の fast-diff（Apache-2.0）は、最終更新が2023年のため採らない。

### ブラウザーの標準機能でまかなうもの

| 役割                       | 標準機能                                                                                       | 補足                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 入力欄                     | `textarea`                                                                                     | IME の変換表示はブラウザーに任せる                           |
| 変換中かどうか             | `compositionstart`・`compositionend`、`KeyboardEvent.isComposing`                              | 変換中の Esc を終了に使わない。確定した文字数の数え方にも使う |
| 全角・半角をそろえる       | `String.prototype.normalize('NFKC')`                                                           | 自前の変換表は持たない                                       |
| 時間の計測                 | `performance.now()`                                                                            | カウントダウンの終わりから、確定後の Esc までを測る          |
| 見た目・ヘッダー・表示切替 | `ui/theme.css`・`ui/header.js`・`ui/theme-toggle.js`                                           | [共通 UI](../../../docs/development.md#共通-ui) に従う       |

## 実装の方向

- NFKC は「㍻」→「平成」のように文字数が変わることがある。結果は打ったままの文字で示すため、正規化した文字と元の文字の対応を保って差分の結果を元の文字へ戻す。
- 左の見本の進み具合は差分ではなく、確定した入力の文字数（改行・空白を除く）で決める。差分の計算は終了時の1回だけ行う。

## 未検証事項

- Windows の Edge（Microsoft IME）と Mac の Chrome（日本語入力）で、変換中に押した Esc を `isComposing` などで見分けられ、変換の取り消しと終了を取り違えないか。
- 長い文章で間違いが多いときの `diffChars` の計算時間。遅い場合は、jsdiff の打ち切りの設定（`maxEditLength`・`timeout`）の利用を検討する。

## 実装時に委ねること

- ファイル構成、関数・型の分け方、TypeScript・ESLint・Prettier などの細かな設定（プロンプト集の設定を参考にする）。
- 配布ファイル名、開発サーバーのポート番号。
- 採用する pnpm・Node.js・各開発用パッケージの版（`diff` は 9 系）。
