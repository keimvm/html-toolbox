# toolbox の開発・リリース検証

## 各ツールからトップへ戻る導線（2026年9月26日）

検証環境：macOS、Node.js 26.10.0、PDF編集の pnpm 12.4.2、Chrome。ブラウザー操作には Computer Use を使用し、Playwrightスキル・CLIは使用していない。

### 変更したこと

- ツールのヘッダー左端に空の `<template id="toolbox-home"></template>` を置き、配布加工時に「← トップへ戻る」の相対リンクへ置き換える。右下の版番号表示は維持する。
- 挿入位置が不足・重複している HTML は収集・梱包で拒否する。ソース・加工前HTMLは変更せず、開発画面にはリンクを表示しない。
- 同じタブで `../index.html` へ移動する。PDF編集の離脱確認・復元処理には変更を加えていない。

## 開発・リリース手順の整理（2026年9月26日）

検証環境：macOS、Node.js 26.10.0、PDF編集の pnpm 12.4.2。

### 変更したこと

- 通常 CI は変更した登録済みツールを3 OSで検証する。README・AGENTS.md・docs だけの変更ではツールのビルドを省略する。共通処理の変更・手動実行は全ツールを検証する。
- Check の起動を main への push と PR に絞り、作業ブランチの push と PR による二重実行を避ける。ブランチ保護に使える固定名の `Check result` を設ける。
- 通常 CI とリリースの依存取得・検証・ビルド・HTML 収集を `tool.yml` にまとめる。リリースはタグのソースから全ツールを検証する。
- `check [ツール名]` と `release <版>` を追加し、登録済みツールの検証と手元の zip 作成を一括で実行できるようにする。
- 設定ファイルの不足、単一 HTML になっていない出力、版番号を付けられない HTML を早い段階で検出する。再作成時に失敗しても同じ版の古い zip を残さない。

### 確認済み

| 確認 | 結果 |
| --- | --- |
| `node --test 'scripts/*.test.mjs'` | 14件成功。変更対象・PR/push の比較範囲・実際の Git での改名と削除・設定不足・単一 HTML・複数ツールの zip・失敗時の停止と古い出力の除去を検査 |
| `node scripts/toolbox.mjs release 2026.09.26` | 固定した依存の取得、PDF編集の整形・Lint・型検査・ビルド・33件のテスト、HTML 収集、zip 作成まで成功 |
| 実際の zip の内容 | `unzip -t` 成功。入口ページと `tools/pdf-edit.html` だけが入り、名前は英数字・ハイフン・ピリオドだけ。HTML は最新のビルドに版番号を加えた内容と一致 |
| CI 対象選択の CLI | GitHub の手動実行イベントを模した入力から、`GITHUB_OUTPUT` に登録済みツールの JSON 配列が出力されることを確認 |
| ワークフローの静的検証 | 公式 actionlint 1.7.12 で全ワークフローを検証し成功。検証用バイナリは一時フォルダに置き、リポジトリの依存には追加していない |
| `git diff --check` | 成功 |

PDF編集のビルドでは、以前からある EmbedPDF 内の `crypto` 外部化の警告が出る。今回、PDF編集のソース・依存関係・画面は変更していない。

### 未確認

- 更新した Check / Release の GitHub 上での実行、リリースへの zip 添付。今回の確認では push・リリース公開は行っていない。
- GitHub のブランチ保護で `Check result` を必須にする設定。既存のツール単位のチェックを必須にしている場合は、文書だけの PR が待機し続けないよう設定を変更する必要がある。
- 会社の Windows・Edge / Mac・Chrome で zip を解凍し、`file://`・ネット接続なしで利用する受入確認。
- ローカルの一括コマンドの Windows 実行。zip 作成コマンドは macOS / Linux を前提とする。

通常 CI での HTML 構成の検査は、外部通信や実行時の動作を証明するものではない。各ツールの実機検証は、そのツールの検証記録で管理する。
