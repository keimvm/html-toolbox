# HTMLツール集「toolbox」
1ファイルのHTMLで作った便利ツールを一つのtoolboxにまとめる。zipで同僚に渡し、会社のWindows PCとMacのどちらでも、インストールせずに使えるようにする。

## 目的・背景
- 便利ツールを1ファイルのHTMLとして作り、1つずつ同僚に渡している。そのためファイルがバラバラになり、どれが最新版か分からなくなる。
- 修正してからリリースするまでの「zipを作る → バージョン番号を付ける → 配る」という一連の作業がすべて手作業で、面倒。
- ツールはGitHubのプライベートリポジトリで管理している。

## 実現したい状態
- 使う人（数人の同僚）は、受け取ったzipを自分のPCに置き、そこからツールを開いて使える。
- 入口のページに一覧があり、ツールをすぐに見つけて開ける。
- 各ツールの画面左上から、入口の一覧へ戻れる。
- 画面にバージョン番号が出ていて、手元の版が古いか新しいかが分かる。
- 作る人（本人）の手作業から、zipの作成とバージョン番号付けがなくなる。
- zipを渡すのは本人が必要なときに直接行う。この部分は手作業のままでよい。

## 扱う範囲 / 今は扱わないこと
扱う
- ツールの一覧を見る入口ページ
- 各ツール
- バージョン番号の表示
- ツールごとの説明

今は扱わない
- カテゴリ分けや検索
- 更新履歴
- 自動で最新版に更新する仕組みや、新しい版を知らせる仕組み（更新したら新しいzipを配り直せば十分）
- 社外への公開（リポジトリはprivateのまま）
- 社内サーバーへの配置（難しいため）

## 大切にしたいこと・制約
- 最優先：使う人が何もインストールせず、zipを解凍して入口ページをChromeまたはEdgeで開くだけで使えること（Macで既定のブラウザがSafariの人は、Chromeで開く）。
- 会社のWindows PCとMacの両方で使えること。対象ブラウザはChromeとEdge。Safariは対象外。
- インターネットにつながらない状態でも動くこと。
- リポジトリはprivateのまま。ツールを誰でも見られる状態にはしない。
- 社内サーバーは使わず、zipで渡す。

## 完了条件
- 作る人がGitHubで日付形式の版のリリースを作ると、版番号付きのzipが手作業なしで出来上がる。ツールの検査かビルドが1つでも失敗したら、zipは出来ない。
- そのzipを同僚が会社のWindows PC（Edge）とMac（Chrome）で、ネットにつながない状態で解凍し、入口ページからツールを開いて使える。入口ページと各ツールに版番号が出る。
- 最初の版には、pdf-editが入っている。
- 配布対象にローカルノート（note-html）を追加し、PDF編集と同じ入口・版番号・zipで配る。
- 詳細は[software-requirements.md](software-requirements.md)を参照。
