## 開発サーバーでの操作確認（2026-09-26）

Claude デスクトップアプリ内蔵のブラウザー（Chromium）で `pnpm dev`（`http://localhost:5175/`）を開いて確認した。OS のフォルダ選択画面は自動操作できないため、`showDirectoryPicker()` をブラウザー内の仮のフォルダ（Origin Private File System）を返すよう差し替えた。

| 確認したこと                                                                                         | 結果                                                                                                        |
| ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| フォルダを選ぶと `prompt-library.json` が作られ、空の一覧が出る（完了条件1）                         | 可                                                                                                          |
| タイトル・本文・タグを入れて追加すると、ファイルに書き込まれる（完了条件1）                          | 可                                                                                                          |
| 編集の保存、確認を経た削除がその時点でファイルに反映される（完了条件2）                              | 可                                                                                                          |
| 2つのタグを選ぶと、両方を含むものだけが出る。削除で使われなくなったタグは選択から外れる（完了条件3） | 可                                                                                                          |
| 開き直すと、許可が残っているため前回のフォルダの一覧がそのまま出る（完了条件5）                      | 可                                                                                                          |

## 未確認のこと

- 配布物（`file://`）を Windows の Edge と Mac の Chrome で開き、ネットにつながない状態で完了条件1〜5が動くこと（完了条件6）。
- 実フォルダでの OS のフォルダ選択・書き込み許可・保存ファイルの作成と上書き。
- `file://` での `navigator.clipboard.writeText()`。
- `file://` の IndexedDB が toolbox の版（解凍先のフォルダ）をまたいで共有され、新しい版で前回のフォルダを開けること。
- ブラウザーを閉じて開き直したときの許可の再要求（「前回のフォルダ（名前）を開く」）。
- 会社の PC の管理ポリシーで File System Access API が止められていないこと。
