# 文章比較 技術構成

元の企画書：[requirements.md](requirements.md)。満たす要件は [software-requirements.md](software-requirements.md) を参照。

## 選定に関わる制約

- toolbox 共通の制約（[要件の制約](../../../../docs/software-requirements.md#制約)）と [ツール追加の手順](../../../../docs/development.md#ツールを追加する) に従う。
- 貼った文章と結果は保存しない。外部へも送らない。

## 採用する技術

| 担当 | 技術 | 役割・採用理由 |
| --- | --- | --- |
| 画面 | Preact ＋ toolbox の共通部品（`src/ui/`） | ほかのツールと同じ部品で作る |
| 差分 | 共通部品 `src/engine/diff`（Rust の WebAssembly）の `diffTokens` | タイピングゲームと同じ差分の本体を使う。理由は下記 |
| 1文字の単位 | `Intl.Segmenter`（書記素） | 「𠮷」・絵文字・濁点つきの半角カナを分けずに比べる |
| 変わらない行の折りたたみ・前後の違いへの移動 | `button`・`Element.scrollIntoView()` | 左右に並べる表示で両側を同時に開くため、`details` ではなくボタンで開く |
| 自動テスト | Vitest | 比べ方（行と文字の差分、まとめ方、打ち切り） |

### 差分の共通部品を使う理由（2026-10-18）

- 利用者の依頼で、タイピングゲームの差分（Rust の WebAssembly）を `src/tools/typing-game/` から共通部品の `src/engine/diff/` に移し、2つのツールで使う。新しい依存は加えない。
- Rust 側は u32 の並びの差分だけを持つ。タイピングゲームはコードポイント（`diffChars`）、文章比較は行・書記素に振った番号（`diffTokens`。同じ文字列に同じ番号を振る）を渡す。Rust 側の変更は説明と引数の名前だけ。
- 差分は編集（追加と削除）の数が最小になり、同じ数の並べ方のうち、なるべく先頭から一致させたものを選ぶ。続いている違いは「後にだけある → 前にだけある」の順で返るため、文章比較は区切りを「削除 → 追加」の順に並べ直して示す。

### 行ごと、その中を文字ごとに比べる理由

- 文章全体を文字ごとに比べると、長い文章では計算が重く、離れた所の同じ文字に一致して読みにくくなる。行ごとに比べて変わったまとまりだけを文字ごとに比べ直すのは、差分の表示で一般的なやり方。
- 違いに挟まれた短い一致は、両側の違いのどちらより長くなければ違いにまとめる（diff-match-patch の `diff_cleanupSemantic` と同じ考え方を、まとまりの中の一段だけで行う）。書き直した文の中で「の」「は」だけが一致して細切れになるのを防ぐ。diff-match-patch そのものは差分の本体を JavaScript で持つため使わない。
- 全体の期限は 500ms（画面を止める時間の上限）。行の差分にこの期限を使い、残りの時間でまとまりの中を比べる。残りがなくても、小さなまとまりは比べられるよう、まとまりごとに最低 5ms を残す。

## 実装時に委ねること

- ファイル構成、関数・型の分け方。
- 比べ直すまでの待ち時間（200ms）、折りたたむ前後の行数（3行）。

## 未検証事項

- 長い文章（数千行の契約書など）での計算時間と、結果の表示の重さ。
- 実際のブラウザー（Windows の Edge、Mac の Chrome）、`file://`・CSP のある配布物での表示と操作。
