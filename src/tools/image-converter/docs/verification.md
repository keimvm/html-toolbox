## 実装前の PDFium の確認（2026-10-03）

PDF編集の依存パッケージ（`@embedpdf/pdfium` 2.15.0）を Node.js で直接呼び、合成 PDF で次を確かめた。作業用のスクリプトで行い、リポジトリには残していない。同じ内容は `tests/pdf.test.ts` に自動テストとして入れた（下記）。

| 確認したこと                                                                                                                                                                                                                                                                                                                                        | 結果               |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `FPDF_CreateNewDocument`・`FPDFPage_New`・`FPDFPageObj_NewImageObj` と `EPDFImageObj_SetJpeg`（JPEG）・`EPDFImageObj_SetPng`（PNG）・`FPDFImageObj_SetMatrix`・`FPDFPage_InsertObject`・`FPDFPage_GenerateContent` で、画像1枚1ページの PDF を作れる。保存後に開き直すと、ページの大きさと画素数が指定どおりで、JPEG は元のバイト数のまま入っている | 可                 |
| 2ページで共有する 1200×900 px の非圧縮画像を、1ページ目で `EPDFImageObj_SetJpeg` により差し替え、`FPDFPage_GenerateContent` で保存すると、2ページ目は元の画像を指したまま残り、容量が十分に減らない                                                                                                                                                 | 確認（対策が必要） |
| 上の場合に、2ページ目の同じ画像オブジェクトを `FPDFPageObj_Transform`（単位行列）で変更済みにしてから `FPDFPage_GenerateContent` すると、両方のページが新しい JPEG を指し、元の画像は保存結果に残らない（約 3.2 MB → 約 35 KB）。文字（Helvetica）は両方のページで取り出せる                                                                        | 可                 |
| `FPDFImageObj_GetRenderedBitmap` の結果のアルファ値で、SMask で半分が透明な画像（最小 0）と不透明な画像（255）を区別できる。`FPDFImageObj_GetBitmap` はマスクを含まないため、この判定には使えない                                                                                                                                                   | 可                 |
| Emscripten の `addFunction` は使える（`ALLOW_TABLE_GROWTH`）が、`EPDFImageObj_SetJpeg` はバイト列を直接受け取るため、`FPDFImageObj_LoadJpegFileInline` の読み込み用コールバックは不要                                                                                                                                                               | 確認               |

## 追加の順番待ちが画像を保持し続ける問題への対応（2026年10月18日）

追加処理の順番待ちに完了だけを残し、最後に追加した画像の配列を保持しないようにした。次の手動確認は未実施。

1. 検証専用の大きな画像を複数追加するか、複数ページの PDF を追加し、すべての変換が終わるのを待つ。
2. 一覧をすべて消し、開発者ツールでガベージコレクション後のヒープを確認する。追加の順番待ちから削除済みの `Item`・元画像・変換結果の Blob が参照されていないことを確かめる。OS のメモリー使用量だけでは判定しない。
3. 再び画像を追加して変換・保存できることを確かめる。
4. 一覧に画像を残してホームへ戻り、別の画像を2枚以上置いて「まとめて1つのPDFにする」を選ぶ。置いた画像だけが PDF に入り、一覧に前からある画像が含まれないことを確かめる。
