## 左の列が「計算中…」のまま変わらない不具合（2026年10月18日）

画像を読み込むと、左の列の画像が「計算中…」のまま見本も容量も出ない、と報告を受けた。`scripts/cdp.mjs` で配布物（`file://`・ネット遮断、10月18日にビルドした版）に 4000×3000 の JPEG を読み込ませて再現した。列の下の合計は1秒以内に変換後の容量になり、「〜枚を計算中」も消えていたため、変換は済んでいて、列の1枚の表示だけが古いままだった。

原因：`@preact/signals` は signal を読む部品を自動で memo 化し、props が変わらなければ親が描き直しても描き直さない。列の1枚（`RailItem`）は開いている画像（`editor.current`）を読む一方で `store.revision` を読んでおらず、`Item` は直接書き換えるため props が同じままになり、変換が済んでも描き直されなかった。`RailItem` で `store.revision` を読むようにした。変換の重さ（WASM 化）や配布物の大きさ（ファイルの分割）とは関係がない。

ユーザーの指示で `node scripts/toolbox.mjs build 2026.10.18`（型検査・ビルド・zip 作成が成功）を実行し、同じ手順（`scripts/cdp.mjs`・`file://`・ネット遮断・ヘッドレス Chrome、4000×3000 の JPEG を1枚）で、読み込んで1秒以内に左の列へ見本と容量（938 KB）が出ることを確かめた。テスト・lint、複数の画像・設定の変更・PDF のページでの確認、実際の写真での手動確認は実行していない。

## 見比べの境目が画像の外まで伸びる不具合（2026年10月18日）

表示欄より小さい画像を「見比べる」で開くと、境目の線が画像の上下の何もない所まで伸び、境目を画像の外へも動かせた。つまみの影（`--tb-elevation` の 30px のぼかし）が小さな画像の上に灰色のしみのように重なって見えた。報告のスクリーンショットと同じ状態を、`scripts/cdp.mjs` で配布物（`file://`・ネット遮断・ヘッドレス Chrome、200×200 の PNG）に読み込ませて再現した。

境目の位置（split）を表示欄の幅ではなく、欄の中で画像が見えている範囲の幅に対する位置にし、線の縦の位置と長さもその範囲に合わせた。拡大して画像が欄からはみ出すときは、これまでと同じく欄の範囲になる。つまみの影は縁だけの細いものにした。

ユーザーの指示で `node scripts/toolbox.mjs build 2026.10.18`（型検査・ビルド・zip 作成が成功）を実行し、同じ手順で確かめた。200×200 の PNG を「全体」で見比べると、境目の線は画像の上下の端まで（長さ 200px）で止まり、つまみの影は画像に広がらない。境目を画像の左右の外までドラッグしても、画像の端で止まる（元の画像が全部隠れる・全部見える）。600×600 の PNG を 200% にして欄からはみ出させると、線は欄の高さいっぱいになる。テスト・lint、実際のマウス・タッチでの操作、ライトの表示、狭い画面での確認は実行していない。
