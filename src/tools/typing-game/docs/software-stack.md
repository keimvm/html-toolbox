## 採用する技術

| 担当       | 技術                                                                    | 役割・採用理由                                                                                             |
| ---------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 画面・処理 | TypeScript ＋ HTML ＋ CSS                                               | プロンプト集・文字コード変換と同じ書き方にそろえる                                                         |
| 画面       | Preact ＋ toolbox の共通部品（`src/ui/`）                                | toolbox の1つのアプリの一部として、ほかのツールと同じ部品で作る。見本の文字は打つたびに直接書き換える |
| 差分       | Rust 1.96 で書いた WebAssembly（`wasm/`、依存なし）                     | 文字単位の差分で、抜け・余分・打ち間違いを取り出す。理由は下記                                             |
| 自動テスト | Vitest、Rust の `cargo test`                                            | 判定（改行・空白の除去、正規化、差分）と進み具合の求め方、差分の本体                                       |

### 差分を Rust の WebAssembly にする理由（2026-10-18）

- 要件の「ずれを吸収して違う箇所だけを示す」には差分の計算が要り、ブラウザーの標準機能にはない。以前は jsdiff（`diff` 9.0.0）の `diffChars` を使っていた（採用理由は下の「以前の構成」）。
- 利用者の指示で、差分の計算を Rust の WebAssembly に切り出した。JavaScript の実装より速く、全く違う長い文章でも打ち切りまでに解ける範囲が広がることを見込む（未測定）。
- 本体は Myers の O(ND) 法を、jsdiff と同じく先頭から進める形にした。編集（追加と削除）の数は最小になり、同じ数の並べ方のうち、なるべく先頭から一致させて抜けを後ろに寄せたものを選ぶ。端に着いた道より外側の対角線は調べない（jsdiff と同じ）ため、途中で終えた場合（見本の残りがすべて抜け）でも速い。
  - 最初は中央の一致（middle snake）で分割統治する形（Myers 1986 の 4b 節、メモリーが文字数に比例する分だけで済む）で書いたが、同じ数の並べ方のうち抜けを途中に置くものを選ぶことがあり、打っている間の見本の位置がずれた（「あいうえ」×100 に「あXいう」×50 と打つと、先頭近くで見本を152文字飛ばした）。打っている位置を求めるには抜けが後ろに寄る必要があるため、先頭から進める形に改めた。
  - 道をたどり直すため、歩数ごとに各対角線の最も進んだ位置を残す。全く違う長い文章ではこれが大きくなるため、残す数が約1678万（i32 で 64 MB）を超えたら、期限を過ぎたときと同じく結果を返さない。全く違う3000字どうしで約1350万に収まる。
- Rust の差分ライブラリ（similar など）は使わない。打ち切りの期限に `std::time::Instant` を使い、wasm32-unknown-unknown では時刻を取れない（取るには wasm-bindgen と、その版に合わせた CLI が要る）。期限を確かめる処理を持つ必要があるため、差分の本体（約150行）を自前で持つ。時刻は JavaScript の `Date.now()` を import して受け取る。
- wasm-bindgen を使わず、`alloc`・`dealloc`・`diff` の3つの関数と線形メモリーで受け渡す。見本と入力はコードポイントの並び（u32）で渡し、結果は `数 << 2 | 種類` の区切りの並びで返す。続いている違いは、入力にだけある文字を先、見本にだけある文字を後にまとめて返す（打った文字のあとに本来の文字を差し込んで示すため）。
- 改行・空白の除去、NFKC、書記素の分け方は、ブラウザーの標準機能のまま TypeScript（`judge.ts`）に残す。Rust に移すと Unicode の表を WebAssembly に持つことになり、標準機能と同じ役割を作り直すため。
- WebAssembly はツールを開いたときに読み込む（`?init`、配布物では Base64 で JavaScript に入る。wasm は約20 KB）。読み込めない環境では、打っている間の進み具合を確定した文字数で進め、判定は違いを示さない結果にする。
- ビルドは `vite/rust.ts` が Vite の起動時（開発サーバー・テスト・ビルド）に cargo で行う。Rust の版と target は `wasm/rust-toolchain.toml` で固定し、rustup が足りない版を入れる。

### ブラウザーの標準機能でまかなうもの

| 役割                       | 標準機能                                                          | 補足                                                              |
| -------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------- |
| 入力欄                     | `textarea`                                                        | IME の変換表示はブラウザーに任せる                                |
| 変換中かどうか             | `compositionstart`・`compositionend`、`KeyboardEvent.isComposing` | 変換中の Esc を終了に使わない。見本を進めるのも確定のときだけ     |
| 全角・半角をそろえる       | `String.prototype.normalize('NFKC')`                              | 自前の変換表は持たない                                            |
| 時間の計測                 | `performance.now()`                                               | カウントダウンの終わりから、確定後の Esc までを測る               |
| 見た目・ヘッダー・表示切替 | toolbox の `theme.css`・`ToolFrame`・`src/lib/theme.ts` | [共通部品](../../../../docs/development.md#共通部品) に従う |
| 1文字の単位                | `Intl.Segmenter`（書記素）                                        | 「𠮷」・濁点つきの半角カナ（「ｶﾞ」）を1文字として数え、色を変える |
| 動き                       | CSS アニメーション・Web Animations API、`prefers-reduced-motion`  | 色の変化・カウントダウン・結果の光。動きを減らす設定では止める    |

## 実装の方向

- NFKC は「㍻」→「平成」のように文字数が変わることがある。結果は打ったままの文字で示すため、正規化した文字と元の文字の対応を保って差分の結果を元の文字へ戻す。
- 左の見本の進み具合は、確定のたびに同じ正規化をした見本と入力を差分（`diffChars`）で比べて決める（`createLocator()`）。違う箇所は求めず、入力の末尾が見本のどこに当たるかだけを使う。
  - 最後の一致箇所を目印にし、その後に打った文字は見本の文字と同じ数だけ進んだものとする。打ち間違いや、一致箇所が見つかる前の打ち始めでも色が進む。
  - 打った文字より多く見本を飛ばした先の一致は、飛ばした数より長いときだけ目印にする。差分は長い一致より編集の少なさを優先するため、打ち間違えた「の」がずっと先の「の」に一致して見本が飛ぶのを防ぐ。
  - 比べる見本は、入力の文字数より200文字先までに限る。大きく飛ばした箇所はこの範囲でだけ追いつく。
  - 打っている間は同期で計算し、`timeout` を 50ms にする。打ち切られたときは確定した文字数（改行・空白を除く）で進める。計算の打ち切りで入力の受け付けを長く止めないための値で、jsdiff では 2000字・5%誤りで約4ms、1万字・10%誤り（繰り返しの多い文章）で打ち切りになった（2026-10-03、Node.js 26・Apple Silicon）。WebAssembly での時間は未測定。

- 置き換え（「天」→「転」）は、打った文字のあとに本来の文字を差し込む。抜けは直前に打った文字のすぐ後ろに置き、見本側で間にある改行・空白も含めて示す。
- 打ち終えた後の判定も同期で計算し、`timeout` を1秒にする（画面を止める時間の上限）。打ち切られた場合は違う箇所を示さず、時間と打った文章だけを出す。jsdiff のときは非同期モード（`callback`）で画面を止めずに計算し、3秒で打ち切っていた。

### 以前の構成：jsdiff を採用した理由（2026-10-03）

- 同じ役割を自前で実装しない。BSD-3-Clause、実行時の依存なし、型定義つき。2026年4月にも更新されている。
- `diff@9.0.0` で試した結果：「今日はいい天気」と「今日いい転気」から、「は」の削除、「天」の削除と「転」の追加を取り出せた。「𠮷」のような補助面の文字も1文字として扱う。
- 比べた候補の fast-diff（Apache-2.0）は、最終更新が2023年のため採らない。

### jsdiff での差分の計算時間（2026-10-03、Node.js 26・Apple Silicon）

`diffChars` を直接呼んで測った。jsdiff は文字列の端に達した後の探索を省くため、途中で終えた場合（見本の残りがすべて抜け）でも速い。WebAssembly の実装では未測定。

| 見本   | 入力                     | 時間   |
| ------ | ------------------------ | ------ |
| 5000字 | 5000字（5%を抜け・誤り） | 7ms    |
| 1万字  | 1000字で終了（2%誤り）   | 5ms    |
| 1万字  | 1万字（10%を抜け・誤り） | 93ms   |
| 3000字 | 全く違う3000字           | 649ms  |
| 1万字  | 全く違う1万字            | 7826ms |

ふつうに打った場合は 0.1 秒以内に収まる。全く違う長い文章のときだけ秒単位になるため、`timeout` で打ち切る（編集の数の上限は文章の長さで適切な値が変わるため使わない。WebAssembly の実装でも同じ）。

## toolbox の1つのアプリへの移行（2026-10-18）

- 判定と時間の表示（`judge.ts`・`time.ts`）は旧コードとテストを移した。時刻次第でたまに失敗していたテストを、確実に再現する形に直した。画面は toolbox の共通部品で作り直した。
- ホームに貼り付けた文章、置いたテキストファイルを見本として受け取る（`sample`）。
- ほかのツールを見ている間は、キー操作・貼り付けに反応しない。

## 未検証事項

- Windows の Edge（Microsoft IME）と Mac の Chrome（日本語入力）で、変換中に押した Esc を `isComposing` などで見分けられ、変換の取り消しと終了を取り違えないか。
- 差分の WebAssembly：計算時間（ふつうに打った場合・全く違う長い文章）、`file://`・CSP のある配布物での読み込み、会社の PC の設定で WebAssembly が止められていないか。
- 配布物に入る Rust の標準ライブラリ（MIT OR Apache-2.0）のライセンス文を、「このアプリについて」に載せるか。今はライセンスの収集が npm のパッケージだけを対象にしている。
