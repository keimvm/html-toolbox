# ローカル Markdown ノートアプリ 仕様書

更新日: 2026-09-26／対象: toolbox 統合版（編集・保存の機能範囲は継続）

実装内容と確認済み・未確認の範囲は [実装・検証記録](VERIFICATION.md) を参照する。

## 1. 目的

任意のローカルフォルダをそのままデータストアとして利用し、配下の Markdown ファイルをノートアプリ風の画面で閲覧・編集する。

アプリ本体は toolbox の1つの HTML（`index.html`）に入れて配布する。Windows・Mac の Chrome または Edge を対象とする。サーバー、外部 API、データベースを必要とせず、File System Access API によって元の `.md` ファイルを直接読み書きする。

本書では、提示された要件を「確定要件」、未指定の動作を具体化したものを「初版の補足方針」として区別する。補足方針は、実装の基準として採用する案である。

### 2.2. 初版の補足方針

- デスクトップ版 Chrome・Edge を対象とする。移行前の画面確認は macOS・Chrome で行っており、Windows・Edge での受入は未確認。
- 解凍した toolbox の `index.html` を開き、ホームから「ローカルノート」を開く `file://` での起動を標準とする。
- CSS、JavaScript、利用ライブラリを HTML に内包し、起動・閲覧・編集・保存にネットワーク接続を要求しない。
- 同時に開くルートフォルダは 1 つ、編集対象のファイルは 1 つとする。
- Markdownファイルの作成・閲覧・編集を対象とし、本文保存は利用者による明示操作とする。
- UI は日本語とし、左側にフォルダツリー、右側に本文を配置する。
- Markdown の文字コードは UTF-8（BOM あり／なし）、改行コードは LF または CRLF を対象とする。
- 未保存変更の保護、保存エラーの表示、保存前の外部変更検知を備える。
- ブラウザ内にフォルダハンドル・選択ノートの相対パス・ツリーの展開状態を記憶し、再読み込みや再起動時に復元する。編集中の本文は永続化しない。

### 2.3. 初版に含めない機能

- ファイル・フォルダの別階層への移動、別名保存、名前変更に伴う参照元リンクの自動更新。添付用の`.assets`とその中のファイル作成はF-11で扱う。
- フォルダの取り込み、クリップボード画像の取り込み、添付の自動整理・削除、画像のサイズ変更・圧縮。
- 全文検索、タグ管理、バックリンク、複数タブ、複数フォルダの同時管理。
- 自動保存、永続的な編集履歴、バックアップ、クラッシュ後の下書き復元。編集中の取り消し・やり直しは対応する。
- クラウドサービスへの直接接続、認証、同期処理、共同編集、競合の自動マージ。
- フォルダの常時監視、Markdown 以外の文書編集、スマートフォン向けの動作保証。

## 3. 利用条件と技術上の制約

### 3.1. 起動方法

1. 利用者が `toolbox-<版>.zip` を任意の場所へ解凍する。
2. Chrome または Edge で toolbox の `index.html` を直接開き、ホームから「ローカルノート」を選ぶ（ホームにフォルダを置いて「ノートとして開く」を選んでもよい）。
3. 画面の「フォルダを開く」から対象フォルダを選択する。
4. ブラウザーが表示するアクセス許可を利用者が承認する。

toolbox の配置場所とノートフォルダの場所は独立してよい。起動のためのインストール、ローカルサーバー、ブラウザ拡張、特別な起動フラグを必須にしない。

File System Access API のピッカーには、安全なコンテキストや利用者の操作などの条件がある。`file://` の扱いは実装に依存するため、API の存在だけで動作可能と判断せず、対象の Chrome・Edge でフォルダ選択から直接保存まで実機確認する。これは実装時の確認事項であり、本書作成時点では実機動作を確認していない。[File System Access 仕様](https://wicg.github.io/file-system-access/#api), [Secure Contexts 仕様](https://w3c.github.io/webappsec-secure-contexts/#is-origin-trustworthy)

起動時に `window.isSecureContext` と必要な API の有無を確認する。利用できない環境では理由を日本語で表示し、ファイル操作を開始しない。`file://` での直接保存が成立しない場合は R-04・R-05 を満たす起動方式を再検討し、サーバー必須へ変更しただけで受け入れ完了にはしない。

### 3.2. フォルダと権限

「任意のローカルフォルダ」は、OS とブラウザーがアクセスを許可する範囲を意味する。システム領域など、ブラウザーが選択・書き込みを制限するフォルダもある。[Chrome の制限対象フォルダに関する説明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access#restricted-folders)

- 利用者が選択したフォルダをルートとし、その配下だけを操作対象にする。
- 読み取り権限と書き込み権限を区別する。読み取りだけが許可された場合でも閲覧できる。
- 書き込み許可は保存・添付追加・ファイル操作に応じて確認・要求する。拒否された場合は編集内容を保持する。
- ブラウザによる権限の失効や再要求に対応し、以前の許可が常に有効とは仮定しない。

### 3.3. 同期フォルダ

- 同期フォルダも通常のローカルフォルダと同じ方法で扱う。
- ファイルの実体をローカルで読み書きできることを利用条件とする。
- オンライン専用ファイルなどを読み出せない場合は、そのファイルの取得失敗を表示し、ローカルで利用可能にしてから再試行できるようにする。
- 保存完了はローカルファイルへの書き込み完了を意味する。クラウドへの同期完了は判定しない。
- 同期クライアントや他のエディタによる更新は、外部変更として扱う。

## 4. 画面構成と基本操作

| 領域 | 表示・操作 |
| --- | --- |
| 画面上部 | toolbox 共通のヘッダー。左上にホームへ戻るボタン、アイコンと「ローカルノート」（押すとほかのツールへ移るメニュー）、表示の切り替え。続けて「フォルダを開く」「再読み込み」、ナビゲーションの開閉ボタンとファイル名（ノートを開いている間だけ）、右側に「書式」、「その他の操作（⋯）」、保存状態、「保存」を配置。ソース表示中は「書式」の位置に「本文に戻る」を表示。フォルダ操作はナビゲーションを閉じていても利用できる。 |
| 左側上部 | 選択中のルートフォルダ名。 |
| 左側 | フォルダの展開・折りたたみ、Markdown ファイル一覧、選択中ファイルの強調。 |
| 本文 | 整形した本文を直接編集するエディタ。補助操作から Markdown ソースへ切り替えられる。 |
| 状態表示 | 読み込み中、未保存、保存中、保存済み、保存失敗、外部変更の検出。 |

ヘッダーの「フォルダを開く」「再読み込み」はアイコンだけを表示し、操作名は読み上げ名とツールチップに残す。

初回は「フォルダを開く」を案内する。次回以降は F-09 の復元を試みる。フォルダ選択後は、ツリーからファイルを選び、閲覧・編集して保存する流れとする。ファイル未選択時は選択を促し、編集・保存操作を無効にする。

本文の縦幅を優先し、書式バーは「書式」から開く重ね表示にする。メニューの外側のクリック・フォーカス移動・Escapeで閉じ、Escapeでは開いたボタンにフォーカスを戻す。「その他の操作」に設定・Markdownソース・エクスポートとフルパスをまとめる。ファイル名のツールチップでもフルパスを確認できる。画面内の使い方、本文下部の文字数・文字コード・保存先表示、ナビゲーション下部の情報欄は設けない。メニューの開閉で本文・選択・編集履歴を作り直さない。

## 5. 機能要件

### F-01. フォルダ選択（R-02、R-06）

- 「フォルダを開く」の操作から `showDirectoryPicker()` を呼び出す。
- 選択したフォルダをルートとして表示する。
- 選択のキャンセル時は、現在のフォルダ・選択ファイル・編集内容を維持する。
- 別フォルダへの切り替え時は、F-06 の未保存変更の確認を行う。

### F-02. フォルダツリー（R-03、R-07）

- ルート配下の階層をたどり、フォルダを展開・折りたたみできる。
- ファイル一覧には拡張子が `.md` のファイルを表示する。拡張子の大文字・小文字は区別しない。
- フォルダを先に、ファイルを後に並べ、それぞれ名前順に表示する。
- 同名ファイルはルートからの相対パスで区別し、別フォルダのファイルを取り違えない。
- Markdown がないフォルダも表示し、対象ファイルがないことを案内する。隠しフォルダという理由だけでは除外しない。ルート直下の`.assets`だけは添付用として除外する。
- サブフォルダは展開時に列挙できる設計とし、ツリーの構築だけを目的に全ファイルの本文を読み込まない。
- 一部のフォルダにアクセスできない場合は該当箇所に表示し、アクセス可能な箇所の閲覧を継続できる。

### F-03. Markdown 閲覧（R-08）

- 選択したファイルの本文を読み込み、Markdown を HTML として整形表示する。
- 初版では、見出し、段落、強調、箇条書き、番号付きリスト、引用、区切り線、インラインコード、コードブロック、リンク、画像、表、タスクリストを表示対象とする。
- 表とタスクリストを除く独自拡張、数式、Mermaid、Wiki リンクなどは対象外とする。
- タスクリストはクリックでチェック状態を編集し、未保存変更として扱う。
- Markdown に記載された生の HTML は文字列として表示し、実行・埋め込みを行わない。
- ソースと直接編集を切り替えても未保存内容を保持し、切り替えでは保存・破棄を行わない。
- ファイルを連続して選択しても、最後に選んだファイルの本文とパスが一致するようにする。

リンク・画像の初版の扱いは次のとおりとする。

| 種類 | 動作 |
| --- | --- |
| ルート内の相対 `.md` リンク | リンク元のフォルダを基準に解決し、アプリ内で対象ファイルを開く。未保存変更の確認を適用する。 |
| ルート内の相対画像 | PNG、JPEG、GIF、WebP を表示する。追加はF-11による。ツリーのノート一覧には含めない。 |
| `http:` / `https:` のリンク | 利用者の Cmd/Ctrl＋クリック、またはフォーカスしたリンクへの Enter で別タブを開く。元画面を維持する。 |
| 外部 URL の画像 | 自動取得せず、代替テキストと画像へのリンクを表示する。 |
| ルート外の相対パス、絶対ローカルパス、解決できない参照 | 自動アクセスせず、参照先を表示して利用できないことを示す。 |
| その他の URL スキーム | 実行可能なリンクとして扱わない。 |

### F-04. Markdown 編集（R-09）

- 整形表示された本文を直接編集できる。「閲覧」「編集」タブは設けない。
- 書式バーから段落・見出し、太字・斜体・取り消し線、リスト・チェックリスト、引用、コード、リンク、区切り線、表を操作できる。
- ヘッダーの「書式」直下に「チェックボックス」を表示する。空の段落・通常の本文・既存リストへ未完了のチェックボックスを付けられる。チェック項目にカーソルがあるときはボタンを選択状態にし、もう一度押すとチェックボックスを外す。本文を保持し、Undo/Redo・保存・再読み込みに対応する。
- 行頭で `- [ ] ` を入力すると ToDo に変換する。リストの最初の段落の先頭では `[ ] ` / `[x] ` / `[X] ` も変換し、完了状態を反映する。通常段落・コード・表セル・エスケープした文字列は変換しない。変換直後のBackspace、Undo/Redo、クリック、次の未完了項目の追加、空項目の保存・再読み込みに対応する。
- コード内の全選択（Mac は Cmd+A、Windows は Ctrl+A）は、そのコードブロックの内容だけを選択する。繰り返しても文書全体へ広げず、コード外やブロックをまたぐ選択では既存のキー操作を維持する。Mac のコード内の Ctrl+A / Ctrl+E は、本文の段落と同じくカーソルのある行の先頭・末尾へ移動し、コードブロック全体の先頭・末尾へは飛ばない。
- 表は先頭行をヘッダーとするGFM表に限定し、セルの編集、行列の追加削除に対応する。セル結合・複数段落・セル内の改行は対象外。Enter / Tab は次のセルへ移動し、最後のセルなら行を追加する。表現できない内容の貼り付けは案内して止める。
- 「Markdownソース」で記法を直接編集し、「本文に戻る」で直接編集へ戻る。画像・添付の追加はF-11、参照先変更はソースから行える。
- 本文中のリンクは通常クリックで編集し、Cmd/Ctrl＋クリックで参照先を開く。相対ノートリンクには未保存確認を適用する。
- 日本語入力、改行、選択、コピー、貼り付け、取り消し・やり直しができる。
- 入力時の変換は Typora の挙動に合わせる。記法だけの段落で Enter を押すと確定し、`` ``` `` / `~~~`（後ろに言語名を書ける）はコードブロック、`---` / `***` / `___` は区切り線と後続段落、`| 見出し | 見出し |` は先頭行を見出しにした2行の表へ変換し、最初の本文セルへ移動する。リストの先頭段落など、そのブロックを置けない位置と表セルでは通常の Enter とする。変換は単独の取り消し単位にし、Undo で入力した記法の文字へ戻す。
- 本文中は閉じ記号の入力で `**太字**` / `__太字__`、`*斜体*` / `_斜体_`、`~~取り消し線~~`、`` `コード` ``、`[文字](URL "題")`、`![代替テキスト](パス)` へ変換する。単語内の `_`、空白で始まる・終わる強調、エスケープした記法、閉じていないバッククォートの後ろ、コード内は変換しない。リンク・画像は Markdown 読み込みと同じ URL 検査を通らなければ文字のまま残す。インラインコードは先に2個入力して間に文字を入れる操作にも対応する。日本語の変換確定後の変換、変換直後の Backspace による記号への復帰、Undo/Redo に対応する。Typora のカーソル位置の記号表示、URL の自動リンク、数式・脚注・ハイライト等は対象外。
- 見出しの先頭で Backspace を押すと標準テキストへ戻す。空のコードブロックで Backspace を押すと、前にブロックがあればコードブロックを取り除いて前のブロックの末尾へ移り、文書・引用などの先頭では標準テキストへ戻す。
- コードブロックの右下に言語（フェンスの情報文字列）の入力欄を置き、Enter・フォーカス移動で確定、Escape で取り消す。バッククォートと改行は除く。言語による色分けは行わない。
- コード内の Tab は半角スペース4個を挿入し、範囲選択中は選択した行を字下げする。Shift+Tab は今の行・選択した行の先頭からタブ1個または半角スペース4個までを除く。Enter は今の行の字下げを引き継ぐ。
- Typora と同じショートカットを持つ。Cmd/Ctrl+0〜6 で標準テキスト・見出し（同じ見出しでもう一度押すと標準テキスト）、Cmd/Ctrl+Shift+\` でインラインコード、Cmd/Ctrl+/ で Markdownソースとの切り替え。Mac は Cmd+Option+C / O / U / Q / T でコード・番号リスト・箇条書き・引用・表、Ctrl+Shift+\` で取り消し線、Cmd+Ctrl+I で画像・ファイルの追加。Windows は Ctrl+Shift+K / [ / ] / Q でコード・番号リスト・箇条書き・引用、Alt+Shift+5 で取り消し線、Ctrl+Shift+I で画像・ファイルの追加。ブラウザーが先に使うキー（Windows の Ctrl+T）は割り当てない。
- 文字だけのクリップボードの貼り付けは Markdown として解釈して書式付きで挿入する。Shift 付きの貼り付けとコード内は文字のまま挿入する。
- コード末尾の空行（空白だけの行を含む）でEnterを押すと、その行を除いて後続の本文段落へ移動する。コード途中の改行・選択置換は維持し、末尾で次の同階層ブロックがコードか後続がない場合は、下矢印でも本文段落を作れる。コード先頭で前の同階層ブロックがコードか前がない場合は、上矢印でも前に本文段落を作れる。上下の矢印で作った段落は、何も入力せずにカーソルを外へ移すと取り除き、取り消しの履歴にも残さない。既存の本文段落の前には増やさない。Shift+Enter / Cmd・Ctrl+Enterによる移動も維持する。ノートを開いただけでは段落を追加しない。
- 入力中の本文と最後に読み込み・保存した本文を区別し、変更がある場合は「未保存」と表示する。
- ファイル名・相対パスを表示し、保存先を判断できるようにする。
- 開いた直後・選択範囲の変更・ソースとの切り替えだけでは原文を変更しない。直接編集後は、意味と表示を保ってリスト記号・空行・URLの表記などを正規化してよい。
- ソースで変更した本文は、直接編集で文書を変更するまで原文を保持する。元の文書状態まで取り消すと、対応する原文も復元する。
- YAML / TOML フロントマターは原文ブロックとして保持する。直接編集用の変換に失敗した場合は原文を保持して表示し、ソース編集へ案内する。
- エディタを入力ごとに再生成せず、IME変換中は保存・表示切り替えを止める。書式・ソースの変更も同じ文書に反映し、ファイル切り替えでは履歴をリセットする。
- 読み込んだ UTF-8 の BOM 有無と改行コードを保存時に維持する。非 UTF-8 や改行コード混在など、対応外の形式を検出した場合は理由を表示して保存を止める。

### F-05. 元ファイルへの直接保存（R-06、R-10）

- 「保存」または `Cmd+S`（macOS）／`Ctrl+S`（その他）で、選択中ファイルの元の場所へ上書き保存する。
- ショートカット操作では ブラウザーのページ保存を起動させない。
- 保存対象のハンドルを使用し、`createWritable()`、`write()`、`close()` の完了を確認する。書き込みの確定にはストリームを閉じる必要がある。[Chrome の既存ファイル保存に関する説明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access#save-changes-to-disk)
- 別ファイルのダウンロードを通常保存の代用にしない。
- 保存前に権限と F-08 の外部変更を確認する。
- 保存中は保存の重複実行と対象ファイルの切り替えを防ぐ。初版では保存中の本文編集も停止し、保存した本文を明確にする。
- 保存処理が成功した場合だけ「保存済み」にする。
- 保存失敗時は本文を保持し、「未保存」の状態を維持したうえで失敗理由と再試行操作を表示する。

### F-06. 未保存変更の保護（R-09、R-10 の補足）

ファイル切り替え、フォルダ切り替え、本文の再読み込みにより編集内容が失われる場合は、次の選択肢を表示する。

| 選択肢 | 動作 |
| --- | --- |
| 保存して続ける | 保存成功後に操作を続行する。保存失敗・権限拒否・外部変更検出時は現在の編集を維持する。 |
| 変更を破棄して続ける | 編集内容を破棄して操作を続行する。 |
| キャンセル | 操作を中止し、編集を継続する。 |

タブを閉じる、ページを再読み込みするなどの離脱時には、未保存変更があれば `beforeunload` によるブラウザ標準の確認を要求する。ホームやほかのツールへ移っても、未保存の本文と編集履歴は保つ（toolbox の1つのアプリの中の移動のため）。本文の自動保存・下書き復元は行わない。フォルダ・表示状態は F-09 に従って復元する。

### F-07. 再読み込み（R-07、R-11 の補足）

- 「再読み込み」により、外部で追加・削除・名前変更されたファイルをツリーへ反映する。
- 現在表示しているファイルの本文も読み直す。未保存変更がある場合は F-06 を適用する。
- ファイルが削除・移動されていた場合はその旨を表示し、保持している本文を勝手に消さない。
- フォルダの常時監視を前提にしない。

### F-08. 外部変更と保存競合（R-10、R-11 の補足）

- 読み込んだファイル内容、または最後に書き込みへ渡して保存成功を確認した内容を、比較用の基準として保持する。
- 保存直前に対象ファイルの最新内容を再取得し、基準と比較する。更新日時・サイズだけに依存せず、内容そのもの、または内容のハッシュで比較する。
- 外部変更を検出した場合は上書き保存を止め、現在の編集内容を保持して「ファイルが外部で変更されています」と表示する。
- 競合時は「編集に戻る」か「編集内容を破棄して再読み込み」を選べるようにする。保持した本文は手動でコピーできる状態にする。
- 初版では、競合を無視する強制上書きや自動マージを提供しない。
- 保存対象が削除・移動されていた場合は保存を止め、同名の新規ファイルを自動作成しない。

この確認は、比較時点までの外部変更を検出するためのものとする。確認後から書き込み確定までに他のアプリが更新する競合を、完全には排除できない。同時編集の排他制御やクラウド側の競合解消は初版の対象外とする。

### F-09. フォルダ・表示状態の復元（R-02、R-07 の補足）

- 最後に使用したルートの `FileSystemDirectoryHandle`、選択ノートの相対パス、展開中フォルダの相対パスを IndexedDB に記録する。本文・編集履歴・カーソル・スクロール位置は含めない。
- 同じブラウザーのプロファイル・同じ HTML の配置場所ごとに記録し、URL のクエリ・フラグメントは区別しない。同じ配置場所の複数タブでは、最後に確定した記録を次回使用する。
- 起動時に記録を検証して `queryPermission({ mode: 'read' })` を確認する。許可済みなら自動復元する。再許可が必要な場合は前回のフォルダ名と「アクセスを許可して開く」を表示し、クリックから直ちに `requestPermission({ mode: 'read' })` を呼ぶ。書き込み許可は従来どおり保存時に要求する。
- 本文はその時点のファイルから読み直し、直接編集の表示で開く。未選択の場合はフォルダだけを表示する。ノートが消えていてもフォルダは維持し、再試行と別ノートの選択を可能にする。フォルダを開けなければ再選択を案内する。
- フォルダ・ノートの読み込み成功時と展開・折りたたみ時に記録する。記録は順序を保って確定し、終了イベントには依存しない。未確定の操作は強制終了時に復元できない場合がある。
- 展開状態は DOM と独立して保持する。遅延列挙中や親を折りたたんだときも子の展開状態を失わず、未展開部分の全件走査は行わない。復元途中の状態を記録に上書きしない。
- ピッカーのキャンセル、未保存確認のキャンセル、フォルダ取得失敗、権限拒否だけでは既存の記録を変更・削除しない。
- 保存領域の不在・例外・ブロック・応答停止、壊れた記録は案内し、手動利用を可能にする。IndexedDB の各操作は最大3秒で待機を打ち切り、本文の編集・保存を妨げない。

実装では `src/session-store.js` に保存境界を分離し、`createApp(window, { sessionStore })` でテスト用の境界を注入できるようにする。戻り値の `ready` は記録の読み出し・権限確認・ルートと選択本文の復元完了を待つ。サブフォルダの遅延列挙は独立して続行する。`flushSession()` はその時点までに要求した記録の完了を待つ。

### F-10. ナビゲーションの幅調整と開閉（R-12）

- 左右の境界のドラッグでナビゲーションの幅を220～600pxに調整する。編集領域は残りの幅を使い、最低360pxを確保する。初期幅は画面幅1050px以下で250px、1500px以上で320px、それ以外は292pxとする。
- 画面上部のファイル名の左のボタンでナビゲーションを開閉する。閉じたときは境界とその余白も除き、編集領域をワークスペース全幅に広げる。開閉で本文・選択ノート・編集履歴・ツリーの展開状態を作り直さない。
- ツールバーとフォルダ操作は利用可能な領域幅に合わせて折り返す。680px以下は上段180pxの上下配置とし、境界を隠す。閉じた場合は上段と段間の余白を取り除く。
- ポインターキャプチャでドラッグを追跡し、終了時に確定する。キャンセル、キャプチャ喪失、Escape、ウィンドウのフォーカス喪失、画面サイズ変更、終了による中断時は開始幅に戻し、記録しない。
- 境界はフォーカス可能な縦の `separator` とし、現在幅と上下限を読み上げ可能にする。左右キーで10px、Shift併用で50px、Home / End で最小 / 最大幅に変更する。開閉ボタンは日本語の操作名、`aria-expanded`、`aria-controls`を持ち、非表示になる領域のフォーカスは開閉ボタンへ移す。
- レイアウトは既存IndexedDBの同じストアに配置場所キー＋`#layout`で保存し、DBバージョンとフォルダ記録は変更しない。形式は `{ version: 1, sidebarWidth: number, sidebarCollapsed: boolean }`。本文やファイルハンドルを含めず、フォルダAPIの対応状況や読み取り許可と独立して読み書きする。
- ドラッグ終了・キーボード調整・開閉時の値を順序どおりに記録する。画面縮小では表示幅だけを制限し、希望幅の記録を変更しない。起動時の遅い記録取得は、その間のユーザー操作を上書きしない。
- 未記録時は初期状態を使う。形式不正・読み書き失敗・3秒のタイムアウト時は利用を続け、既存の重要な通知を上書きせず、レイアウトを記憶できない旨を一度だけ案内する。

`src/layout.js` に操作を分離し、`createApp(window, { sessionStore, layoutStore })` で保存境界を注入できる。`ready` はF-09に加えてレイアウト記録の読み込み完了も待つ。`flushLayout()` は呼び出し時点までのレイアウト記録完了を待つ。

### F-11. 画像・添付ファイルの追加（R-13）

- 整形された本文へのファイルドロップと、「挿入・操作」→「画像・ファイルを追加」に対応する。複数ファイルは受け取った順序で追加し、一回のUndo・Redoで参照を戻せる。
- 本文のドロップ位置を示し、段落・表・リスト・段落を作れるブロック間へ挿入する。コード・原文ブロック内は追加前に案内する。ファイル選択では選択開始時のカーソル位置を使う。
- ノート未選択、閲覧のみ、IME変換中、他の処理中は追加しない。ソース画面や本文外へのファイルドロップでもブラウザの画面遷移を抑止する。フォルダを含むドロップは追加せず案内する。通常のテキスト・本文内のドラッグ・貼り付けは維持する。
- ルート直下の`.assets`は初回追加時に作成し、既存なら再利用する。同名の通常ファイルがある場合は中止する。保存名は元の名前・拡張子を基本にUUIDを付け、禁止文字と長さを調整する。既存名との衝突は再生成する。元ファイルは移動・圧縮・変換しない。
- ルートの書き込み許可を確認し、必要時は「許可して追加／キャンセル」を表示する。許可ボタンのクリックから直接`requestPermission({ mode: 'readwrite' })`を開始する。拒否・取消では添付も参照も追加しない。
- 追加中は編集・保存・ノート切り替え・再追加を止め、処理中表示とページ離脱確認を行う。各ファイルの書き込みと`close()`の成功後に参照を挿入する。一部失敗時は成功分だけを挿入し、未追加名を表示する。途中ファイルは削除を試み、削除できなければ残存パスを知らせる。
- PNG・JPEG・GIF・WebPは標準の画像記法、それ以外は元の名前を表示する標準のリンク記法を使用する。ノートの階層に応じた`.assets/…`または`../.assets/…`等の相対参照をエンコードして保存する。表示用Blob URLは本文に含めない。
- ファイルの実体は追加時点で保存する。ノート本文は従来の明示保存で確定する。Undo、未保存本文の破棄、参照の削除でも添付の実体は自動削除しない。
- `.assets`内の画像以外（`.md`も含む）は添付参照に分類する。通常の本文リンクと同じ修飾キークリック・Enterで開く。読み取り専用表示とリンク編集も対応する。
- PDF・UTF-8テキスト（txt/md/csv/log/json）・対応画像・音声（mp3/wav/ogg/m4a/flac）・動画（mp4/webm/mov）は別タブで開く。形式・コーデックによって表示できない場合は通知からダウンロードできる。HTML・SVGなどその他は`application/octet-stream`としてダウンロードする。MIMEは拡張子の許可リストで決める。
- 別タブは取得前に確保してopenerを切り離す。取得失敗時は空タブを閉じ、タブ作成拒否時はダウンロードを案内する。プレビュー用Blob URLはタブを閉じたとき、ダウンロード用は開始後60秒、残るURLはアプリ終了時に解放する。ルート外へのアクセス・外部画像の自動取得は禁止する。

ファイル保存と添付を開く処理は`src/assets.js`、対象ノート・権限・処理状態はアプリ、挿入位置・履歴は直接編集層で管理する。既存の画像ノードとリンクを使い、独自の文書形式を追加しない。

### F-12. 表示調整（R-14、R-17）

- チェック済み項目の文字・リンク・強調を薄いグレーにする。取り消し線を追加せず、チェック解除・Undo/Redoで戻す。子タスクは自身のチェック状態を使い、画像とチェックマークは淡色化しない。
- 上部の「その他の操作（⋯）」→「設定」の本文フォントサイズで14・16・18・20・24pxを指定する。初期値は16px。本文・ソースに適用し、見出し・表・コードも比例させる。画面幅を変更しても選択サイズを優先する。
- UIフォントは端末にインストールされたフォント名を入力または候補から指定する。空欄で標準に戻り、指定フォントがない場合も標準へフォールバックする。ナビゲーション・メニュー・ダイアログに適用し、本文・ソース・出力文書のフォント書体は変えない。外部フォントは取得しない。
- UIフォントサイズは90・100・110・120・130%から指定する。初期値は100%で、ファイルツリーは12px（幅1500px以上は13px）を標準とする。ナビゲーション・ヘッダーの操作・メニュー・ダイアログの文字に倍率を掛け、本文・ソース・出力文書、案内画面の見出し、toolbox 共通のヘッダー左上の一角は変えない。
- CSS変数で変更し、文書モデル・選択・履歴・未保存本文を作り直さない。既存のIndexedDBに配置場所別の`#display`キーで`{ version: 3, fontSize, uiFont, uiScale }`を記録する。旧`version: 1`の文字サイズ、`version: 2`の文字サイズとUIフォントは引き継ぐ。フォルダ・レイアウト記録は変更しない。
- 遅い読み出しで操作を巻き戻さず、変更順に記録する。未知の形式・保存障害では標準サイズまたは現在のサイズで利用を続け、短い通知を表示する。
- 画面内の使い方は設けず、ライセンス全文は配布HTMLの非表示テンプレート内に保持する。

### F-13. HTML・PDFエクスポート（R-15）

- 上部の「その他の操作（⋯）」→「エクスポート」から「HTMLをダウンロード」「PDFに保存」を選ぶ。対象は現在のノートの最新本文で、ソース画面と未保存の編集内容も含む。元ファイルへの書き込み、保存済み状態への変更は行わない。
- Markdown描画の静的出力モードを共用し、本文用CSS・文字サイズ・チェック状態・フロントマター原文を保持する。操作UIや直接編集の案内は含めない。
- HTMLはUTF-8の単独ファイルとし、元ノートの拡張子を`.html`に置き換える。ローカル画像をdata URLに変換して内包し、Blob URLやスクリプトを残さない。出力文書のCSPはスクリプト・通信を禁止し、画像は埋め込みdata URLだけを許可する。アプリ側のCSPは変更しない。
- PDFは画像の読み込み・デコード後に印刷専用DOMを用意し、ブラウザーの印刷画面を開く。文字サイズ・チェックの淡色化を反映し、長いコードは折り返し、表や画像・見出しの改ページを調整する。`@page`のmarginを0にしてブラウザのタイトル・日時・URLやファイルパス・ページ番号を抑止し、各ページの本文余白はpaddingで16mm確保する。本文中の見出し・日付は保持し、用紙・保存先は印刷画面で指定する。
- 添付や別ノートは表示名と参照先の文字表記を残す。外部Webリンクと文書内の見出しリンクは利用可能にする。外部画像は自動取得せず、ローカル画像の取得・デコード失敗は本文と通知へ案内して出力を続ける。
- 未選択・IME変換中・他の処理中は実行しない。準備中は編集・切り替え・重複操作を止め、失敗時は本文を保持して再操作できる状態に戻す。取得は30秒、画像デコードは15秒で待機を打ち切る。
- 印刷終了・キャンセル・例外で一時DOM、印刷用状態、タイトルを戻し、画像URLを解放する。HTMLダウンロード用URLは60秒後かアプリ終了時に解放する。アプリ終了後に戻った取得結果から出力しない。

### F-14. ファイル・フォルダ操作（R-16）

- 各行の「⋯」からファイル・フォルダの追加、名前変更、削除を選ぶ。ルート行では追加だけを表示する。ファイル行の追加先は同じ親フォルダ、フォルダ行ではその直下とする。新規ファイルは空のMarkdownで、拡張子がなければ`.md`を補う。
- 名前入力は日本語・空白を許可し、区切り文字・制御文字・予約名`.assets`・末尾のピリオド等を拒否する。同名項目、大文字小文字・Unicode正規化だけが異なる項目の上書きは止める。
- 確定ボタンからルートの書き込み許可を要求する。取消・権限拒否では変更しない。処理中は編集・保存・別操作を止め、ページ離脱確認を要求する。
- 名前変更は対象全体を新しい名前へコピーし、バイト内容を検証し、元の内容・実体に変更がないことを再確認してから元の項目を削除する。隠しファイル、Markdown以外、空フォルダも含む。コピー・検証に失敗すれば元の項目を削除せず、コピーが残る可能性を通知する。自動再試行や上書きはしない。
- 開いているノートとその親フォルダの名前変更では、パス・ハンドル・展開状態・復元先を更新し、未保存本文・選択・編集履歴を保持する。他のノート内のリンクは更新しない。
- 削除は対象パスと、フォルダ内の全ファイル件数を表示して確認する。Markdown以外も削除対象で、ゴミ箱に入らないことを示す。編集中ノートを含む場合は保存・破棄・キャンセルを先に確認する。削除成功後にだけ選択本文と復元先を解除する。
- 確認前のスナップショットと実行前の内容・実体を比較する。開いているノートは読み込み・保存時の基準とも比較する。外部更新・削除・差し替えがあれば中止し、本文を保持する。

`src/file-operations.js`にファイル操作と検証を分離する。通常フォルダの名前変更には全体のコピー分の空き容量と、内容を検証するメモリが必要。APIには排他的作成や複数操作をまとめるトランザクションがないため、比較直後の外部変更を完全に防ぐことはできない。削除失敗・ページ終了時は一部だけ削除されたりコピーが残る場合がある。同期中や他アプリで同時編集している対象への操作は避け、必要なデータは事前にバックアップする。[Chromeのファイル移動・削除の対応範囲](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access#renaming-and-moving-files-and-folders)

## 6. データと非機能要件

## 8. 実装時に確認・記録する事項

- 対象 Chrome・Edge の `file://` におけるピッカー表示、読み取り許可、書き込み許可、直接保存の実機結果。
- 採用する Markdown パーサーと描画の安全対策、対応記法、ライセンス。
- フォルダ数・ファイル数・単一ファイル容量に対する応答時間と、実測に基づく動作確認範囲。
- 利用可能な同期フォルダでの動作結果と、オンライン専用ファイルを読み出せない場合の案内。
- 実機で再現できない保存失敗やタイミング依存の競合について、模擬テストで確認した範囲と残る制約。

## 9. toolbox との接続

- コード内の選択と下矢印は ProseMirror の `keymap`・`TextSelection`・`exitCode` を使い、選択範囲と段落を作る条件、上下の矢印で作った空段落を外へ移ったときに除く `Plugin`（`appendTransaction`）だけを追加する。ToDo は既存のリスト入力ルールに続く `InputRule` で `list_item.checked` を設定し、既存の NodeView と Markdown 保存へ接続する。標準のスキーマには ToDo の入力変換がないため、この判定だけをツール側で持ち、新しい依存や文書形式は追加しない。
- OS・ブラウザーの標準機能とライブラリを優先する [共通の実装方針](../../../../docs/development.md#実装方針) に従う。上部メニューは Popover API と CSS アンカー配置で開閉・配置し、対象は Chrome・Edge 129 以降とする。HTML 出力の画像は FileReader で data URL に変換する。
- 復元情報・レイアウト・表示設定は、DB 名 `local-notes-session`・ストア `sessions` に、固定のキー（`toolbox#session`・`toolbox#layout`・`toolbox#display`）で保存する。記録形式は従来どおり。ダイアログの操作欄は toolbox の `theme.css` の `.tb-dialog-actions` を使う。
- toolbox の1つのアプリ（2026-10-18）として、依存関係は toolbox 全体の `package.json` で持ち、Vite で1つの HTML に入れる。振る舞いの JavaScript とテストは旧 note-html から移し、テストは Vitest で動かす。画面の骨組み（`markup.js`）は toolbox の共通ヘッダー（`ToolFrame`）の中に置く。
- 配色・ボタン・入力欄・ダイアログは toolbox 共通の `theme.css` を使い、OS のダークモード設定とヘッダーの切り替えに従う。画面の CSS は `.nh` の中に閉じ、本文の CSS（`document.css`）は本文の要素にだけ効かせて画面とエクスポートで共用する。本文の書体は変えず、印刷と HTML エクスポートは常にライトにする。添付のダウンロード（`src/lib/download.ts`）、本文外へのファイルドロップの抑止（`src/ui/drop.ts`）は toolbox の共通処理を使う。
- ホームや画面に置いたフォルダを開く（`openFolderHandle`）。置いただけでは読み取りの許可を求められない場合は、通知の「許可して開く」を押してもらう。ほかのツールを見ている間は ⌘S・⌘/ に反応しない。
- 版の切り替えでも、固定のキーにより復元情報と表示設定を引き継ぐ（旧構成の記録は配置 URL ごとのキーだったため、1つのアプリにした最初の版でだけフォルダを選び直す）。保存済みの Markdown と添付は元のノートフォルダに残る。
